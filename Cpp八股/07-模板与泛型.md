# 07 · 模板与泛型

## Q1. 函数模板和类模板？实例化发生在什么时候？

**答要点**

- 模板是编译期代码生成机制；用到具体类型时**实例化**
- 定义通常放头文件（或显式实例化）
- 编译错误常又臭又长，因为在实例化点展开

---

## Q2. 全特化与偏特化？

**答要点**

- **全特化**：针对完全确定的模板实参给出实现
- **偏特化**：只针对类模板；固定部分参数或加约束形式（函数模板用重载/SFINAE/concepts 代替偏特化）
- 常用于类型特质（type traits）

---

## Q3. 什么是 SFINAE？

**答要点**

- **Substitution Failure Is Not An Error**：替换失败不是错误，而是丢掉该重载候选
- 用于在模板重载集里按类型能力启用/禁用接口（`enable_if`、`void_t` 等）
- C++20 起大量场景被 **Concepts** 替代，可读性更好

---

## Q4. 可变参数模板怎么用？典型场景？

**答要点**

- `typename... Args`，包展开、递归或 fold expression（C++17）
- 场景：`emplace`、日志、元组、转发工厂、类型列表元编程

---

## Q5. 完美转发与引用折叠规则？（简述）

**答要点**

- 万能引用 `T&&` + `std::forward`
- 引用折叠：`T& &` → `T&`，`T&& &&` → `T&&` 等
- 目的是既绑左值又绑右值且不丢类别

---

## Q6. CRTP 是什么？解决什么问题？

**答要点**

- **Curiously Recurring Template Pattern**：`template<class D> class Base { ... static_cast<D*>(this) ... }; class Derived : public Base<Derived>`
- **编译期多态**：无虚表间接，可内联
- 用于静态接口、混入、减少虚调用开销

---

## Q7. 类型擦除（type erasure）常见实现？

**答要点**

- 虚基类接口 + 堆上派生包装
- `std::function`、`std::any`、自定义 concept-based 设计
- 代价：分配与间接；收益：统一异构可调用/可存储

---

## Q8. C++20 Concepts 相对 SFINAE 的好处？

**答要点**

- 约束写在接口上，错误信息更友好
- `requires` 子句表达能力清晰
- 逐步替代繁琐 `enable_if` 技巧（遗留代码仍常见 SFINAE）
