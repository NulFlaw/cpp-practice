# 05 · STL 容器

## Q1. `vector` 的底层原理？扩容策略？

**答要点**

- 动态数组：连续内存；`size` 与 `capacity`
- 空间不足时分配更大块、搬迁元素、释放旧块（扩容因子实现相关，常见约 1.5～2 倍）
- 均摊 O(1) 尾插；中间插入/删除 O(n)
- 随机访问 O(1)，缓存友好

**追问**：为什么搬迁后迭代器、指针、引用可能全部失效？

---

## Q2. `vector` 哪些操作导致迭代器失效？

**答要点**

- **扩容**相关：`push_back` / `emplace_back` / `insert` / `reserve` 不足时再分配 → 几乎全部失效
- **插入/删除**：插入点及之后迭代器失效；`erase` 返回新的下一位置迭代器
- `reserve` 足够时可避免扩容失效；`shrink_to_fit` 可能再分配

## Q3. `vector` vs `list` vs `deque`？

**答要点**

| | vector | list | deque |
|--|--|--|--|
| 结构 | 连续数组 | 双向链表 | 分块数组 |
| 随机访问 | O(1) | O(n) | 均摊 O(1) |
| 头插 | O(n) | O(1) | 均摊 O(1) |
| 尾插 | 均摊 O(1) | O(1) | 均摊 O(1) |
| 缓存 | 最好 | 差 | 较好 |
| 失效 | 扩容影响大 | 仅涉及时节点 | 两端插删时中间引用常仍有效（实现相关，需谨慎） |

默认优先 `vector`，除非有明确链表/双端需求。

## Q4. `map` 和 `unordered_map` 区别？

**答要点**

| | `map` | `unordered_map` |
|--|--|--|
| 底层 | 红黑树（平衡 BST） | 哈希表 |
| 复杂度 | 查找/插入 O(log n) | 均摊 O(1)，最坏 O(n) |
| 有序 | 按 key 有序 | 无序 |
| 对 key 要求 | 可比较 `<` | 可哈希 + 相等 |

**追问**：哈希冲突怎么解决？负载因子？rehash 时迭代器？

## Q5. 为什么 `unordered_map` 的 key 需要哈希和相等？自定义类型怎么用？

**答要点**

- 特化 `std::hash<Key>` 或传自定义 Hash；提供 `operator==` 或 Equal
- 相等的对象必须有相同哈希（一致性）
- 哈希质量影响冲突与性能

---

## Q6. `string` 的 SSO（小字符串优化）？

**答要点**

- 短字符串存在对象内部缓冲区，避免堆分配
- 超过阈值后改用堆
- 阈值与布局是实现细节（libc++ / libstdc++ / MSVC 不同）
- 影响：短串拷贝/移动成本、取 `data()` 后失效规则仍要注意

---

## Q7. `reserve` 和 `resize` 区别？

**答要点**

- `reserve(n)`：保证 capacity ≥ n，**不改变 size**，不构造新元素（对 vector）
- `resize(n)`：改变 size；变大则默认构造/填充新元素，变小则析构多余元素

---

## Q8. 迭代器分类有哪些？对算法意味着什么？

**答要点**

- 输入 / 输出 / 前向 / 双向 / 随机访问
- 算法要求决定容器是否适用（如 `sort` 需要随机访问 → list 不行，要用 `list::sort`）
- C++20 起 Concepts 把这些约束说得更清楚

---

## Q9. `emplace` 和 `push`/`insert` 区别？

**答要点**

- `emplace*`：原地构造，完美转发参数，少一次临时对象
- `push_back(T{})` 可能先构造临时再移动/拷贝
- 对不可拷贝类型、构造昂贵类型更友好；注意 `explicit` 构造与括号歧义

---

## Q10. `vector<bool>` 有什么问题？

**答要点**

- 特殊位压缩代理实现，不是真正的 `bool` 容器
- 无法得到正常的 `bool&`；并发、部分泛型代码会出坑
- 需要真正 bool 序列时用 `vector<char>` / `deque<bool>` / `bitset` 等按场景选择
